# Project Definition

Turn current user intent and available evidence into the smallest coherent project definition worth developing.

## Use when

- defining or materially redefining website purpose, audience, positioning, content, functionality, quality, or acceptance;
- a new project domain would force implementation to invent meaning;
- a reference/example is being considered as a possible requirement;
- current Foundation is insufficient for the next development decision.

Do not use for routine implementation of already-defined behavior or bounded maintenance where wider project meaning cannot change the fix.

## Truth classes

Keep these distinct:

```text
APPROVED
→ explicit current project-owner decision

SOURCE-BACKED
→ established by relevant current evidence

DERIVED
→ necessary implication from approved/source-backed truth

PROPOSAL
→ one recommended direction among plausible options

UNKNOWN
→ insufficient evidence/decision
```

Reference websites, old chats, previous projects, and common industry patterns are not automatically Hellocraft requirements.

## Critical behavior

- Recover what is already known before asking the user to repeat it.
- Prefer a clear recommendation over a long questionnaire.
- Ask only when a material choice cannot be resolved responsibly.
- Challenge invented complexity, weak taxonomy, and vague marketing language.
- Preserve explicit negative requirements and deferred boundaries.
- Do not promote internal team disciplines into client-facing services without evidence.
- Do not infer Hellocraft portfolio attribution from historical conversation context when the owner has said they will provide the list.

## Current Hellocraft guards

Current approved positioning:

> Hellocraft Studios is a game studio focused on Minecraft.

Current portfolio inventory is deferred. Do not invent projects/categories before the owner supplies the list.

Current services/capability taxonomy is unresolved. Do not recreate rejected structures merely because they are common on websites.

## Foundation update

Persist accepted durable meaning into:

```text
docs/foundation/01-project-overview.md
docs/foundation/02-product-requirements.md
```

Create another Foundation owner only when `docs/README.md` expansion gate is actually satisfied.

Do not create per-session planning reports, approval files, research-summary archives, or versioned replacement docs.

## Completion

A definition pass ends when the requested scope is either:

- sufficiently defined for its next responsible step; or
- blocked by one exact material missing input/decision.

Update `CONTEXT.md` only when stable orientation changes and `docs/knowledge/next-action.md` only when active continuation changes. Then STOP.
