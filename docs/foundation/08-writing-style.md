# Writing Style Guide

This guide defines how Hellocraft Studios should write public website copy.

The direction is based on current official websites from established Minecraft creators and studios, including Noxcrew, Gamemode One, Blockworks, Everbloom Games, Shapescape, Spark Universe, and Blockception.

The goal is to learn from their communication patterns without copying their wording.

## Core voice

Hellocraft should sound:

```text
confident
clear
creator-led
Minecraft-native
friendly
practical
professional
```

It should not sound like a generic creative agency, a software company, or a marketing pitch generator.

A useful balance is:

```text
professional = high
friendly     = medium
playful      = light
technical    = only when useful
salesy       = low
```

## What the reference studios do well

### Gamemode One

Useful pattern:

- very short, confident statements;
- talks like a game studio rather than an agency;
- uses normal words such as games, studio, community, products, players;
- lets the projects carry most of the credibility.

Use this for Hellocraft's headline confidence and brevity.

### Noxcrew

Useful pattern:

- warm first-person voice;
- creator/team identity is visible;
- explains Minecraft work in concrete terms;
- enthusiasm comes from the subject, not from exaggerated adjectives.

Use this for About, Careers, and community-facing language.

### Blockworks

Useful pattern:

- strongest model for client/project writing;
- explains what the client needed, what the team built, and what happened;
- uses simple sentences such as "we were asked" and "we built";
- project results are shown only when there is a real result to show.

Use this as the main model for Hellocraft Project Detail pages.

### Everbloom Games

Useful pattern:

- approachable and enthusiastic;
- easy to understand for players;
- Careers copy feels like people talking to people;
- project descriptions focus on what the player can actually do.

Use this for player-facing descriptions and Careers.

### Shapescape

Useful pattern:

- explains Minecraft in terms of the client's goal;
- useful for visitors who understand their business need but not Minecraft production;
- combines a clear outcome with a playable idea.

Use this when Hellocraft needs to speak to brands, events, museums, exhibitions, or other non-Minecraft-native clients.

### Spark Universe

Useful pattern:

- concise company description;
- directly names the kinds of Minecraft work it creates;
- clear project and Careers language.

Use this for short company descriptions and role summaries.

### Blockception

Useful lesson:

The simpler Marketplace-oriented copy is useful, but some current agency-style sections rely heavily on phrases such as immersive digital experiences, brand DNA, high impact, and similar marketing language.

Hellocraft should avoid that direction unless a phrase communicates a specific fact that cannot be said more plainly.

## Main writing rules

### 1. Say what Hellocraft does early

A visitor should not need to decode a slogan before learning that Hellocraft makes Minecraft projects.

Prefer:

```text
We build Minecraft games and experiences.
We design and develop Minecraft projects.
We create custom Minecraft worlds and gameplay.
```

Avoid opening with abstract statements about imagination, digital transformation, innovation, or the future of experiences.

### 2. Use active verbs

Prefer:

```text
build
design
develop
create
make
play
explore
test
work
help
```

Avoid replacing simple verbs with marketing language such as:

```text
leverage
elevate
activate
redefine
revolutionise
unlock potential
deliver impact
```

### 3. Use Minecraft-specific nouns when they add clarity

Useful words include:

```text
Minecraft
world
game
gameplay
map
level
player
project
system
Add-On
Marketplace
Bedrock
3D art
```

Use Bedrock, Marketplace, Add-On, or other technical terms only when the page actually needs that detail.

### 4. Prefer "we" and "our"

Public copy should usually sound like the team speaking directly.

Prefer:

```text
We built...
We worked on...
Our role included...
We created...
```

Use "Hellocraft Studios" when introducing the company, in metadata, or when clarity requires the full name.

### 5. One clear claim at a time

Do not stack several abstract claims into one sentence.

Prefer:

```text
We build Minecraft projects for players, partners, and organisations.
```

Avoid:

```text
We create innovative, immersive, boundary-pushing digital experiences that transform brands through play.
```

### 6. Show proof after the claim

If copy says Hellocraft is experienced, high quality, trusted, successful, or widely used, the page should show the project, client, result, or other evidence that supports it.

Do not use reputation adjectives as a substitute for proof.

### 7. Keep headlines short

Typical target:

```text
3–9 words
```

A headline should usually communicate one idea.

Good patterns:

```text
We build Minecraft experiences.
Featured projects.
What we do.
How we work.
Careers at Hellocraft Studios.
Tell us about your project.
```

Avoid headlines that read like advertising slogans unless the wording is genuinely useful and specific.

### 8. Keep body copy compact

For normal website sections:

```text
1–3 short sentences
```

Use longer paragraphs only when a Project Detail page needs context.

## Words to use carefully

These words are common on studio websites but quickly become generic when repeated:

```text
immersive
innovative
unique
passionate
creative
engaging
exciting
high-quality
boundary-pushing
bespoke
world-class
```

They are not banned, but use them only when the sentence becomes more accurate, not simply more impressive.

## Words and phrases to avoid by default

```text
brand DNA
next-level
digital landmark
creative solutions
cutting-edge
revolutionary
transformative experiences
future-forward
seamless ecosystem
360-degree solution
unlock your brand's potential
where imagination meets innovation
```

Also avoid internal production language in public copy unless the visitor needs it.

## Page-by-page guidance

### Home

Purpose:

```text
who we are
→ what we make
→ selected projects
→ short About context
→ contact
```

Home should be confident and short. Do not explain every service or process here.

### Portfolio

Portfolio intro should be minimal. Real projects should do most of the talking.

Project cards should prioritise:

```text
project name
one clear description
real media
simple action
```

Do not add marketing copy around every project card.

### Project Detail

Use this structure when the information exists:

```text
Project name
Client / partner, if public
One-sentence project description

The project
→ what the client/project needed

What we made
→ what was actually built or developed

Player experience
→ what players do, see, learn, or experience

Our role
→ Hellocraft's specific contribution

Results
→ only verified results

Links / credits
→ only when useful
```

Strong sentence patterns:

```text
[Client] asked us to...
We built...
We designed...
Players can...
Our role included...
The project was released...
```

Avoid turning a case study into a long self-congratulatory story.

### About

Answer these questions plainly:

```text
Who is Hellocraft?
What kind of Minecraft work does the team do?
How does the team normally approach projects?
What real experience supports that?
```

Do not write a manifesto unless there is a real company reason for one.

### Careers

Careers should sound like people talking to future teammates.

Prefer:

- clear description of the work;
- what the role will actually do;
- how the team works;
- location/remote expectations;
- application requirements;
- honest hiring status.

Avoid exaggerated culture claims that could apply to any company.

### Contact

Keep it practical.

Useful wording:

```text
Tell us about your project.
What are you building?
Who is it for?
What do you need help with?
```

Separate business enquiries from Marketplace/player support later if both responsibilities exist.

## CTA style

Prefer short standard actions:

```text
View project
View portfolio
About Hellocraft
Contact us
Get in touch
Apply
Learn more
```

Avoid decorative CTA wording that makes the action less obvious.

## Project description rule

Player-facing Marketplace content can be more energetic than company copy.

For player-facing project descriptions:

```text
start with what the player gets to do
→ name the main mechanic or fantasy
→ mention one or two distinctive features
→ keep the energy in the verbs
```

For client-facing project descriptions:

```text
start with the project goal
→ explain what was built
→ explain the player's experience
→ show verified results when available
```

Do not use the same paragraph for both audiences when their questions are different.

## Final review checklist

Before approving public copy, ask:

```text
[ ] Can a visitor understand the sentence on the first read?
[ ] Does it say something specific about Hellocraft or the project?
[ ] Is there a simpler verb available?
[ ] Is every strong claim supported?
[ ] Is Minecraft terminology used only when helpful?
[ ] Does the sentence sound like a game studio rather than an agency?
[ ] Could this sentence appear unchanged on 100 unrelated agency websites?
[ ] Are we talking about the project more than ourselves?
[ ] Is the CTA obvious?
```

If a sentence could belong to almost any creative agency, rewrite it with a concrete Minecraft/project fact.

## Current Hellocraft direction

The preferred Hellocraft voice can be summarised as:

> **A Minecraft game studio speaking clearly about what it makes, how it works, and what players or clients get from the project.**

Use confidence from the work itself. Do not manufacture confidence through jargon.
